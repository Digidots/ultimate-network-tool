📚 MTU Discovery Tool - Complete Guide

🎯 What is MTU?

Maximum Transmission Unit (MTU) is the largest packet size that can be transmitted over a network without fragmentation. The standard MTU is 1500 bytes for Ethernet networks.

🔬 How MTU Path Discovery Works

This tool discovers the PATH MTU (bottleneck) by sending packets with the Don't Fragment (DF) bit set to each hop:

How it works: 1. Sends packets with increasing TTL (1, 2, 3...) and DF=1 2. Each router decrements TTL and forwards the packet 3. When TTL reaches 0, router sends back "TTL Expired" 4. If packet is too large, router sends "Fragmentation Needed" 5. Binary search finds exact MTU for each hop

⚠️ CRITICAL LIMITATION - The Bottleneck Problem:

WHAT WE CAN DISCOVER: Scenario A - Declining MTU: Hop 1: 1500B ✓ (We discover this) Hop 2: 1400B ✓ (We discover this - packet reaches it) Hop 3: 1300B ✓ (We discover this - packet reaches it) Result: We see the bottleneck narrowing at each hop WHAT WE CANNOT DISCOVER: Scenario B - Bottleneck then Higher MTU: Hop 1: 1500B ✓ (We discover this) Hop 2: 1400B ✓ (We discover this - BOTTLENECK!) Hop 3: 2000B ❌ (We CANNOT discover this!) Why? Hop 2 drops packets > 1400B BEFORE they reach Hop 3! We never learn that Hop 3 supports 2000B. REAL-WORLD EXAMPLE: Your PC : 1500B Router 1 : 1500B ← We see 1500B VPN Gateway: 1400B ← We see 1400B (BOTTLENECK!) Internet : 9000B ← We see 1400B (can't discover true 9000B!) The VPN tunnel limits us to 1400B, hiding any higher MTU beyond it.

What the results actually mean:

  • Path MTU = Lowest MTU from your PC to this hop (cumulative bottleneck)
  • Once you hit a bottleneck, all following hops show the SAME MTU
  • You can only discover the MINIMUM MTU in the path, not individual hop capabilities
  • To discover Hop 3's true capacity, you'd need to test FROM Hop 2

⚙️ How Don't Fragment (DF) Bit Works

Test with DF=1 (Don't Fragment): Router sees 1501 byte packet with DF=1 Router's MTU = 1500 bytes Router DROPS packet and sends ICMP error Tool detects: Path MTU = 1500 bytes Test with DF=0 (Fragmentation Allowed): Router sees 1600 byte packet with DF=0 Router's MTU = 1500 bytes Router FRAGMENTS packet into smaller pieces Destination receives and reassembles Tool detects: Hop Capacity = 1600 bytes

🔍 Understanding the Results Table

Path MTU (DF=1): Shows cumulative bottleneck from your computer to this hop

Hop Capacity (DF=0): Shows what this specific hop can handle

Status Indicators:

  • ✅ Optimal: MTU is 1500 bytes (standard Ethernet)
  • ⚠️ Path Limited: This hop can do more, but earlier hop limits it
  • ⚠️ Reduced: This hop is the actual bottleneck
  • ❌ Unreachable: Hop did not respond to probes

🔧 How It Works

This tool uses the Windows ping command with the Don't Fragment (-f) flag to perform MTU discovery. This approach:

  • Works without administrator privileges
  • No special dependencies or raw socket access needed
  • Uses native Windows networking (ICMP Echo Request/Reply)
  • 28 bytes overhead (20B IP header + 8B ICMP header)
  • Reliable and compatible with most networks

💻 Windows Network Adapter Limitations

⚠️ IMPORTANT: Windows PCs have a default maximum MTU of 1500 bytes on Ethernet adapters.

Default Windows MTU Limits: • Ethernet: 1500 bytes (standard) • Wi-Fi: 1500 bytes (standard) • VPN: Typically 1400-1450 bytes (encryption overhead) • PPPoE: 1492 bytes (1500 - 8 byte PPPoE header)

Enabling Jumbo Frames (MTU > 1500):

  • Open Device Manager → Network Adapters
  • Right-click your network adapter → Properties
  • Advanced tab → Look for "Jumbo Packet" or "Jumbo Frame"
  • Change from "Disabled" to desired size (e.g., 9000 bytes)
  • NOTE: All devices in the path must support jumbo frames!
  • WARNING: Misconfiguration can break network connectivity

Why use jumbo frames?

  • Reduces CPU overhead (fewer packets to process)
  • Improves throughput for large file transfers
  • Common in data centers and storage networks
  • Requires compatible switches and routers

🛡️ No Administrator Required

This tool works without administrator privileges! It uses the built-in Windows ping command which:

  • Runs with normal user permissions
  • Automatically sets the Don't Fragment bit with the -f flag
  • Controls TTL with the -i flag for hop-specific testing
  • Handles ICMP responses natively

💡 Troubleshooting Tips

  • If hops show "Unreachable", the router may not respond to ICMP or blocks fragmentation messages
  • VPN users: Expect lower MTU (typically 1400-1450 bytes due to encryption overhead)
  • PPPoE users: Standard MTU is 1492 bytes (1500 - 8 byte PPPoE header)
  • If Path MTU and Hop Capacity differ significantly, investigate that router for configuration issues
  • Some corporate firewalls may block ICMP entirely - results may be incomplete

📈 Best Practices

  • Always compare Path MTU vs Hop Capacity for each hop
  • Run multiple tests for consistency
  • Test during normal network conditions (not during heavy traffic)
  • Document results before/after network changes
  • If many hops show unreachable, the network may block ICMP probes
